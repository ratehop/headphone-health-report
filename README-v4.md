### 配色切换失效的根因

`style.css` 里 11 条 `[data-color="xxx"]` 与兜底的 `:root { --accent: ... }` **特异性完全相同**（都是 0,1,0），
而兜底那条写在最后 —— 同分时后写的赢，于是 **`:root` 永远覆盖掉所有 `[data-color]` 规则**，
JS 明明把 `data-color` 改对了，强调色和环境光却一动不动。

修法：兜底规则改成 `:root:not([data-color])`，只在 HTML 上没有任何 `data-color` 时才生效；
同时把兜底值改成新的橘光橙。**以后加配色必须写在兜底规则之前**，否则同样会失效。

### 顶栏糊影的根因

`.topline` 上写着 `padding-top: env(safe-area-inset-top)`，但 `.topbar` 的高度是写死的 `52px`。
在 iPhone（安全区约 59px）上内容盒被压成 0，40px 的按钮溢出到顶栏盒子之外 ——
WebKit 会把溢出 `backdrop-filter` 盒子的内容卷进背景模糊层，于是叉号和齿轮变成了两团糊影。
修法：把 `padding-top` 挪到 `.topbar` 自身（背景一起往下延伸，形成「出血」），`.topline` 只留 52px 内容高度。

### 滑页手势的根因

翻页手势的白名单只有 `.carousel`（设备轮播）和 `.seg`（周期选择），**漏了概览页顶部的 `.chips`（设备切换条）**，
所以设备超过 2 个时，滑设备栏会直接翻到第二页。现在改成通用检测：沿 DOM 往上找
`overflow-x: auto/scroll` **且确实溢出**（`scrollWidth > clientWidth`）的祖先，命中就锁掉翻页手势；
容器内容没溢出（设备只有 1~2 个）时依然可以翻页，手感不被牺牲。

### 新增调试钩子

- `?color=azure` —— 直接指定配色（不写进 localStorage），配合 `?demo=1` 可逐个主题核对对比度。
- `?demo=1` —— 生成示例报告，无需真实 ZIP。
- `?audit=1` —— 输出真实布局测量值。

### PWA：为什么之前「添加到主屏幕」后进不去

两个叠加的坑：

1. **`manifest.webmanifest` 原来放在 `assets/` 下**。manifest 里的 `start_url: "./"` 是**相对 manifest 自身 URL** 解析的，不是相对网站根目录 —— 所以它解析成 `/assets/`。iOS 主屏图标启动时打开的就是 `/assets/`，网关那里没有默认首页，返回的是 nginx 的目录列表页（你听到的「Directory listing for…」）。现在 manifest 移到**站点根目录**，`./` 才正确解析为根。
2. **分享网关的鉴权**。链接必须带 `?sharecode=XXX`，否则网关返回 403「链接不完整」。iOS 主屏图标启动时不会带上浏览器里的 cookie，所以 `sharecode` 必须写进 `start_url`。同理 `<link rel="manifest">` 也要带 sharecode，否则浏览器抓 manifest 时被网关拦掉，退化成普通网页快捷方式（没有图标、没有独立窗口）。

`build-manifest.sh` 负责生成这两处：

```bash
SHARE_CODE=WRWALA5PVK ./build-manifest.sh
```

> **换分享链接后要重跑一次这个脚本**，把新的 sharecode 写进 manifest。
